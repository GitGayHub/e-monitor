## Исправление

Раньше HTML-first совсем не обновлял официальный расход, выводился только локальный счётчик. Теперь сервер получает eBay Analytics независимо от исчерпания Browse, не чаще15мин на ключ, максимум1ключ за проход. OAuth/Analytics не расходуют Browse-запросы. Выбирается именно buy.browse; отдельная квота bulk getItems не прибавляется.

Последний успешный замер сохраняется в существующем checkpoint DB, без значений ключей. Ошибка запроса сохраняет прежние данные/время, не превращается в0%. Если официального замера нет, локальный счётчик явно обозначен как оценка.

В APK кнопка «Обновить расход» загружает последний опубликованный runtime_status GitHub. Она не запускает новый прогон и не обещает расход «прямо сейчас». Показаны дата статуса, источник и дата замера каждого ключа, остаток с десятичным процентом (20/5000 =0,4%), срок сброса. Старый период после reset отмечен устаревшим. При сетевой ошибке прежний снимок остаётся видимым. Повторные нажатия во время загрузки не создают параллельных запросов.

JSONschema1 сохранена, новые поля необязательны. Фильтры, цены, подписки, порядок и история не менялись.

## Второй ключ — пока не подтверждён

После просьбы пользователя взять настройку на себя пара из изображения сохранена агентом в зашифрованных GitHub secrets EBAY_CANDIDATE_CLIENT_ID / EBAY_CANDIDATE_CLIENT_SECRET, отдельно от рабочей ротации. Значения не коммитились и не включались в отчёт. Временные локальные копии удалены.

Отдельный read-only GitHub run40149719029 получил оба значения, но eBay ответил401 invalid_client / client authentication failed. Причина (точность исходных значений, активность набора или другая настройка аккаунта) ещё не доказана. Не объявлять2рабочих ключа и не подменять рабочий ключ невалидным.

Предыдущий run40149207511 получил пустой слот2: на тот момент пользователь подтвердил сохранение, но GitHub API не показывал новых secrets ни в одном из двух репозиториев. Затем агент сохранил кандидата сам. Основные EBAY_CLIENT_ID / EBAY_CLIENT_SECRET не менялись.

QA workflow qa-api-usage.yml проверяет кандидата OAuth→Analytics→один Browse GET только при свободной квоте, не меняет config/seen и ничего не отправляет в Telegram. Сейчас нужен доступ к странице Application Keys eBay для проверки статуса/исходных значений; в подключённом Chrome вкладка отсутствовала. Фоновое создание Chrome-вкладки не поддерживает visibility. Не менять видимость репозиториев и не выдавать отсутствие доступа за успех.
