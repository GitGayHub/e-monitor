# eMonitor 0.111 — проверка всех вариантов названия

Общая приёмка **26 товаров / 104 корзин остаётся незавершённой**. Этот этап исправляет очередь запросов. Работа выполнена на скрытом эмуляторе Android 16.

## Подтверждённая ошибка

Если первый вариант названия исчерпывал 20 секунд на получение страницы, следующий проход снова начинал с него. В воспроизведённом сценарии за три запуска ни второй, ни третий вариант не получили попытки. Поэтому объявление, находившееся под другим названием, могло вообще не попасть на проверку.

Это воспроизведение использует настоящий разбор названий, обработку запросов и отдельную базу. Внешний источник заменён управляемым тестовым ответом. Оно доказывает ошибку очереди, но не измеряет задержку живого eBay.

## Что исправлено

- Перед обращением к сайту сохраняется следующий вариант запроса. После перезапуска процесс продолжает с него.
- При выборе всех форматов чередуются покупка и аукцион одного названия, затем следующего. Аукционы не стоят за всеми вариантами покупки.
- Изменение названий или условий сбрасывает соответствующую очередь. Другие рынки и отдельные проходы по заканчивающимся аукционам имеют собственные позиции.
- После ошибки текущая пачка живого поиска останавливается. Следующая попытка выполняется по обычному расписанию: дополнительных немедленных запросов нет.
- Статистика продолжает собирать полное объединение запросов. Незавершённая проверка не подтверждает отсутствие товаров и не создаёт полную выборку для медианы.

Прежние ограничения сохранены: пауза между попытками, бюджет времени, квота API, полное описание перед положительным решением, аукционные этапы и защита от повторной отправки. Нулевой ответ API после ошибки HTML по-прежнему не означает «Не найдено».

В базе сохраняются идентификатор поиска, хэш условий, позиция очереди и время. Старые цены и описания для нового решения не используются. Правила модели, дефектов и цены не изменились; версия структуры ценовой истории осталась 27.

Новые проверки охватывают перезапуск, все названия и форматы, ожидание допустимой попытки, истёкшее время, изменение условий, разные рынки, прерывание сетевого обращения, исчерпанную квоту API и различие ошибки и пустой выдачи. Отдельная проверка проходит настоящий цикл мониторинга: объявление из второго варианта получает полное описание перед вызовом подменённой отправки. Сообщения в Telegram этот тест не отправлял.

В повторе исходного сценария первый вариант завершился таймаутом, второй и третий вернули объявление. Все три получили попытки. Результаты отдельных проходов сохранили признак неполной проверки. Файлы `ALIAS_110.json` и `ALIAS_111.json` содержат результаты до и после.

Сравнение 31 описания проверяет релевантность. Оно не подтверждает все текущие цены, минимумы или доставку. Локальные тесты также не заменяют проверку настоящего рабочего прогона.
