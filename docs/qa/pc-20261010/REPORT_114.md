# eMonitor 0.114 — лишние ожидания при проверке eBay

Исправлены два источника задержки браузерной проверки. Полная приёмка 26 товаров и 104 корзин остаётся незавершённой.

## Что изменилось

Сервер проверял наличие капчи после ожидания карточек товара. В рабочем логе три попытки занимали около 12,05 с от начала варианта запроса до сообщения о капче. Теперь распознанная капча завершает попытку сразу после перехода, до обработки cookies и ожидания карточек до 8 с. Обычная загружающаяся страница продолжает ждать результат; капча, появившаяся позднее, также сохраняет ошибку.

Кроме того, браузер пробовал три кнопки cookies, даже если баннера не было или он уже закрылся. Теперь нажимается только видимая кнопка, после принятия обработка прекращается.

HTML остаётся основным источником, API — ограниченным резервом. Паузы между запросами, квота, полное описание перед положительным решением, очередь вариантов, аукционные этапы и защита от повторной отправки сохранены. Нулевой API после ошибки HTML не подтверждает отсутствие объявлений. Изменение убирает лишнее ожидание; оно не снимает ограничение доступа, выставленное eBay.

Новые проверки выполняют настоящий обработчик страницы с управляемым браузером без сети: ранняя и поздняя капча, перенаправление на splash, обычная загрузка, настоящая пустая выдача, отсутствующий и видимый баннер. Внешний путь HTML → API проверен с найденным товаром и с нулевым ответом. Ожидания карточек и кнопок до исправления воспроизведены отдельными красными прогонами. Старые 3970 примеров не менялись.

Пять методов DetailsReplay входят в число 374. Полные 32 описания — входные данные одного из них, а не дополнительные 32 тестовых метода. Это проверка релевантности, не всех живых цен или времени доставки.
