# Проверка 0.076 — 14 октября 2026

Исправлены два воспроизведённых сбоя: остановка серверных проходов по жёсткому лимиту времени и открытие старой формы редактирования вместо нового поиска. Общая проверка всех 25 товаров и 100 корзин ещё не завершена.

## Серверная очередь

Два прежних рабочих запуска завершались с кодом 124 после 480 секунд. Теперь перед новым запросом, описанием или уведомлением монитор проверяет оставшееся время и сохраняет очередь. Уже начатую отправку Telegram он не отменяет. У очереди есть сохранённый следующий поиск; перезапуск процесса не возвращает каждый проход к первому товару. Удалённые и отключённые поиски исключаются.

Отложенная проверка имеет явную причину «не завершена по времени». Непроверенные описания не становятся подходящими объявлениями, а частичная история не подтверждает медиану или скидку. Исчерпание времени не преобразуется в «Не найдено». Статистика сохраняет прежний путь проверки; фильтры модели, дефектов, цены и времени аукциона не ослаблены.

## Добавление, редактирование, удаление и восстановление

На эмуляторе 0.075 путь «редактировать → сохранить → закрыть → добавить» воспроизводил ошибку: заголовок «Новый поиск», старый запрос и цена 45 €, кнопка «Готово, закрыть», сохранённая цель редактирования. Новое сохранение могло относиться к прежнему товару. [До исправления](editor-leak075.png).

0.076 создаёт отдельную сессию при каждом открытии формы. Новая форма очищает запрос, цель редактирования, результат сохранения и старое превью. Сохранение захватывает исходные условия и идентификатор до фоновой операции. Результат прежней сессии не перезаписывает новую форму; два быстрых нажатия не запускают два сохранения.

Проверено через настоящее приложение на скрытом эмуляторе Android 16:

| Действие | Результат |
|---|---|
| Добавить отдельный тестовый поиск `emonitor qa076` | 49 → 50 записей, прежние поиски сохранены |
| Повторно открыть «Добавить» после сохранения | Пустые поля, кнопка добавления; прежний запрос не перенесён |
| Удалить только тестовый товар | 50 → 49, запись появилась в восстанавливаемой корзине |
| Восстановить тестовый товар | 49 → 50; прежний ID и все условия сохранены; изменилось только время обновления |
| Повторно удалить тестовый товар | В действующих поисках снова исходные 49 записей |
| Сохранить существующую мышь с прежними условиями, затем открыть «Добавить» | Пустая новая форма; старые 45 € и цель редактирования отсутствуют |

Сверены все исходные бизнес-поля 49 поисков в базе до и после. [Сверка](emulator-crud076.json), [пустая новая форма](editor-new076.png), [создание](editor-created076.png), [корзина](editor-trash076.png), [восстановленный поиск](editor-restored076.png).

Эмулятор использует отдельную копию данных, без секретов GitHub и Telegram, с отключёнными фоновыми заданиями и уведомлениями. Ошибка отправки настроек в GitHub в этих снимках ожидаема: проверяется локальное сохранение при отсутствии связи. Настоящие рабочие настройки этим тестом не менялись. Физический телефон по текущему указанию владельца не использовался; на нём остаётся 0.075.

Задержка сохранения одновременно с переходом в новую форму защищена кодом, но её отдельная проверка с медленной сетью ещё не проведена. Это не объявляется пройденным сценарием.
