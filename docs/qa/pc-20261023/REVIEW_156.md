# 0.156: очередь пересчитывается во время прохода, S Pen различается с телефоном

Сервер раньше фиксировал порядок поисков в начале шестиминутного прохода. Медленный запрос увеличивал ожидание остальных товаров, но список не пересчитывался. Приоритетный товар мог оставаться в конце уже устаревшего списка. Теперь после каждого товара заново учитывается прошедшее время; веса определяются полным каталогом, каждый ID выполняется максимум один раз за проход. Сохранение продолжения очереди, лимиты API, полная проверка описания/цены и дедупликация сохранены. В журнал добавлен dispatch с ID и приоритетом, без продавцов и секретов.

Контроль реального цикла воспроизводился: second→third→first вместо second→first→third. После исправления проходит, остальные проверки продолжения очереди и 48 товаров сохранены. На read-only production checkpoint c1c19425 iPhone находился на28-м месте. При условных28с/товар и13 попытках динамическая очередь ставит его11-м. Это моделирование, а не замер живой задержки. Порядок пользователя, включая Pixel18, не менялся; <=15мин для всех не подтверждено.
