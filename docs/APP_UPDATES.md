# Публикация обновления APK

Публичный e-monitor/main/mobile/android_release.json сообщает последнюю версию. Сам APK остаётся в закрытом e-monitor-android; доступ через asset API с существующим GitHub token(readAndroid). Ключ не помещать в URL/манифест, репозиторий не открывать.

После повышения app/version.properties, успешных проверок и сборки на этом ПК:

    python tools/publish_apk_release.py --commit <проверенный полный SHA Android> --publish

Без --publish только проверка APK и план. Нужны GITHUB_TOKEN, JAVA_HOME, Android build-tools; GitHub CLI надёжно передаёт большие файлы. Подпись должна совпадать с установленной APK. Новый случайный debug key в Cloud клиент отвергнет. Не коммитить keystore.

Сначала draft/immutableasset, затем GitHubdigest и повторное авторизованное скачивание, после этого release и объявление манифеста. Опубликованный versionCode с другими байтами не повторять. При сбое проверить существующий draft/asset и продолжить эту публикацию, не перезаписывать неизвестный бинарник. Android независимо проверяет размер/hash/пакет/версию/подпись.

Автопроверка при открытии/возвращении с интервалом не чаще5мин, ручная кнопка без ожидания. Загрузка по кнопке, установка с разрешением и подтверждением Android. Это не бесшумная установка. Старая APK до166 требует одной обычной установки166.

ВерсияAPK и rules сервера различаются. Schema1 совместима, Telegram не зависит от открытия APK; совпадение локального отбора требует одинаковых правил.
