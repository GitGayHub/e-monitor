# Продолжение eMonitor с телефона

Обновлено 8 октября 2026. Основная проверка eMonitor **ещё не закончена**.

## Как продолжить именно эту работу

Подключи ChatGPT на Android к этому Windows-ПК через **Codex / Remote**. Работа останется на ПК, поэтому сохранятся файлы, текущие правки, эмулятор и локальные доказательства проверки. Возможность зависит от версии приложения и доступности функции для аккаунта. [Мобильный Codex](https://learn.chatgpt.com/docs/mobile).

1. На ПК открой настройки приложения ChatGPT/Codex: **Settings → Connections → Control this Mac or PC → Set up / Add**.
2. На своём телефоне отсканируй показанный QR-код, войди в тот же аккаунт и рабочее пространство и подтверди соединение.
3. На телефоне открой **Codex**, либо **Remote**, если раздел пока называется так. Выбери этот ПК, проект **ebay apk**, существующий чат **«Сверить фильтры APK и Telegram»**.
4. Оставь ПК включённым, подключённым к интернету и приложение работающим. В Connections можно настроить поддержание бодрствования ПК.

Это стандартная привязка устройств; GitHub для неё отдельно настраивать не требуется. Подтверждение привязки и авторизации выполняет владелец телефона. На момент подготовки этого файла подключение телефона к Codex ещё **не подтверждено**. [Подключение устройств](https://learn.chatgpt.com/docs/remote-connections).

Сообщение для существующего чата:

> Продолжай eMonitor по MOBILE_CONTINUE.md и актуальному audit/2026-10-04/CURRENT_STATUS.md. Сначала проверь фактическое состояние сервера и эмулятора. Телефон сейчас не трогай; я отдельно напишу, когда можно. ПК используй скрыто. Доведи HTML после квоты, полные описания, сверку фильтров и настоящую доставку Telegram до проверки по исходному плану. Не объявляй работу завершённой по одним тестам.

Если создаётся новый чат на **том же подключённом ПК**, выбери проект ebay apk и передай тот же текст, добавив пути ниже. Лучше продолжить существующий чат: в нём сохранён весь контекст.

## Эмулятор и следующая проверка

Создан отдельный `EMonitor_QA_API36`, Android 16, ADB `emulator-5580`. Драйвер Google AEHD 2.2 установлен после подтверждения пользователя; проверка ускорения успешна. Эмулятор запускается без окна, 2 ядра, программная графика. Физический телефон сейчас нужен пользователю — не запускать на нём приложение, не нажимать и не читать его состояние до нового разрешения.

Для восстановления соединения с уже работающим эмулятором после перезапуска ADB: `adb connect 127.0.0.1:5581`. Проверить `adb devices` и `sys.boot_completed` перед установкой.

APK в эмуляторе получает рабочие настройки из GitHub, но не получает токен записи GitHub и токен Telegram. Изменения, сделанные для проверки интерфейса в эмуляторе, не должны менять рабочий сервер. Ключи API не нужны для чистой HTML-проверки.

## Сохранение существующей работы

Оба репозитория имеют незакоммиченные изменения. Не делать reset/clean и не выполнять слепой pull. Старая Python-копия внутри APK — справочная; рабочий бот находится в `C:\VibeCoding\e-monitor`.

Публикация кода выполняется `audit/2026-10-04/publish_checked_sources.py`: preflight, затем выбранный `bot` или `android` с `--publish`. Он сохраняет параллельные изменения рабочего состояния GitHub и не публикует весь аудит. Перед публикацией проверить его список файлов и актуальность последнего опубликованного commit.

Проверки Python: `python qa/run_unit_tests.py` из основного бота — отдельные временные config/seen/SQLite, сеть запрещена. Android: `testDebugUnitTest assembleDebug` с JDK 21. Временные эксперименты не должны менять production config, mode, recipient, seen или поиски.

Приватные резервные копии, токены, пароль конфигурации, базы приложения и полный каталог аудита на GitHub не публиковать. Использовать существующие локальные секреты на подключённом ПК. Окна ПК не переключать и не активировать; браузерные проверки вести скрыто. Привязка Remote не отменяет это пользовательское ограничение.
