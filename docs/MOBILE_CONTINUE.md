# ПК ↔ GitHub ↔ Codex Cloud: продолжение eMonitor

Обновлено 8 октября 2026. Нужен именно **Cloud с выключенным ПК**. Общая приёмка eMonitor ещё не завершена.

## Один раз подготовить Cloud

В ChatGPT на вебе/ПК выбери **Work in → Cloud → Create environment**. Добавь оба репозитория: `GitGayHub/e-monitor` и `GitGayHub/e-monitor-android`, ветки **codex/cloud-work**. Для существующего окружения проверь выбранные ветки. Укажи Java 21, Python 3.12 и Android SDK 36. После подготовки и проверки нажми Publish. Затем на телефоне в Codex выбери это облачное окружение. ПК может быть выключен. [Официальная настройка Cloud](https://learn.chatgpt.com/docs/environments/cloud-environments).

Подготовка окружения в аккаунте ещё не подтверждена: в скрытом браузере сейчас нет веб-входа ChatGPT. Опубликованные файлы и GitHub-ветки сами по себе не создают окружение OpenAI.

Задание для настройки окружения:

> Подготовь оба репозитория e-monitor и e-monitor-android из codex/cloud-work. Прочитай AGENTS.md и docs/WORK_STATE.md. Установи зависимости requirements.txt бота, Python 3.12, Java 21, Android SDK 36 и инструменты Gradle. Запусти tools/cloud-check.py из Android с настоящими --bot-dir и --android-dir. Для ручного чтения eBay нужен Playwright/Chromium и доступ к ebay.de/ebaydesc.com. Не запускай monitor.py в рабочем normal-режиме и не используй production Telegram. После успешной подготовки покажи результаты и опубликуй окружение для моего аккаунта.

## Как передавать работу туда и обратно

**Перед дорогой:** код обоих проектов, тесты и `docs/WORK_STATE.md` должны быть опубликованы в GitHub. Общий checkpoint указан в `docs/CLOUD_CHECKPOINT.json`. Файлы, оставшиеся только на ПК, в Cloud недоступны. Наши облачные ветки отделены от рабочего автомониторинга.

**В дороге:** открой существующую Cloud-задачу, либо новую задачу в подготовленном окружении. Читай WORK_STATE из GitHub. В конце этапа сохраняй код **и обновлённый WORK_STATE** коммитом/PR. Если Cloud создал отдельную ветку, укажи её в WORK_STATE и сообщении для возвращения. Облачные изменения не должны остаться только в контейнере. [Продолжение облачных задач](https://learn.chatgpt.com/docs/cloud).

**После возвращения:** в локальном проекте скажи «Продолжай с Cloud». Агент сначала читает состояние GitHub и выполняет `python tools/cloud_sync.py --check` в Android-репозитории. Затем применяет совместимые изменения через `--apply`, запускает тесты и продолжает с пункта WORK_STATE. Скрипт сохраняет резервную копию исходников; при конфликте отказывается от всего применения. Если работа в другой ветке, передать её через `--bot-ref` / `--android-ref`. Он не выполняет reset/pull и не перезаписывает режим, конфигурацию, секреты или историю отправок.

Само включение ПК не запускает синхронизацию: она выполняется при продолжении задачи агентом по AGENTS.md. Отдельный постоянно работающий фоновый сервис не устанавливался.

Сообщение с телефона:

> Продолжай eMonitor в Codex Cloud по AGENTS.md и docs/WORK_STATE.md в обоих репозиториях. Работай над незавершёнными исправлениями и независимой проверкой eBay. Сохраняй изменения и актуальный WORK_STATE в GitHub для следующего продолжения на ПК. Физический телефон и локальный Telegram в Cloud не проверены; не выдавай их за выполненную проверку. Не меняй production mode/recipient/searches/seen.

Сообщение после возвращения:

> Продолжай с Cloud. Проверь новые коммиты codex/cloud-work в обоих репозиториях, прочитай WORK_STATE, безопасно объедини их с локальными правками через cloud_sync.py, запусти тесты и продолжи следующий незаконченный пункт. ПК скрыто; физический телефон пока не трогай.

## Что проверяется без рабочего ПК

Cloud может редактировать оба проекта, проверять общие JSON-примеры и Python-тесты, собирать APK и читать доступные публичные страницы eBay. Реальная установка на физический телефон, его UI, сохранённые локальные данные и чтение окна AyuGram остаются для этапа на ПК. Наличие GitHub Actions сервера не даёт Cloud автоматически его секреты.

Проверка чистых репозиториев также подготовлена как GitHub Actions **Cloud readiness - both repositories** в Android. Успешный CI и опубликованное окружение — отдельные доказательства.

APK в эмуляторе получает рабочие настройки из GitHub, но не получает токен записи GitHub и токен Telegram. Изменения, сделанные для проверки интерфейса в эмуляторе, не должны менять рабочий сервер. Ключи API не нужны для чистой HTML-проверки.

## Сохранение существующей работы

Оба репозитория имеют незакоммиченные изменения. Не делать reset/clean и не выполнять слепой pull. Старая Python-копия внутри APK — справочная; рабочий бот находится в `C:\VibeCoding\e-monitor`.

Публикация кода выполняется `audit/2026-10-04/publish_checked_sources.py`: preflight, затем выбранный `bot` или `android` с `--publish`. Он сохраняет параллельные изменения рабочего состояния GitHub и не публикует весь аудит. Перед публикацией проверить его список файлов и актуальность последнего опубликованного commit.

Проверки Python: `python qa/run_unit_tests.py` из основного бота — отдельные временные config/seen/SQLite, сеть запрещена. Android: `testDebugUnitTest assembleDebug` с JDK 21. Временные эксперименты не должны менять production config, mode, recipient, seen или поиски.

Приватные резервные копии, токены, пароль конфигурации, базы приложения и полный каталог аудита на GitHub не публиковать. Использовать существующие локальные секреты на подключённом ПК. Окна ПК не переключать и не активировать; браузерные проверки вести скрыто. Привязка Remote не отменяет это пользовательское ограничение.
