Физический телефон, production Telegram и production manifest — не менять. Этот документ имеет приоритет над старым qa/FIRST_TASK.md и qa/WORKFLOW.md в вопросах очереди/старта; нельзя выполнять их прежнее предложение blind git pull/reset.

## Старт

Прочитай `AGENTS.md`, `docs/WORK_STATE.md`, `docs/MOBILE_CONTINUE.md`, этот файл и `docs/qa/CLOUD_ACCEPTANCE_QUEUE_2026-10-08.json`. Сверяй текущие HEAD; старые SHA и статусы CI не подтверждают новый HEAD.
2. Источник истины пользовательских настроек — **только для чтения** `GitGayHub/e-monitor/main/mobile/app_sync.json`. Сохранённая матрица `qa/results/ACTIVE_SEARCH_MATRIX_2026-10-08.md` (в Android: `docs/qa/...`). Проверено: **24 товарные группы, 48 сохранённых поисков, 46 включённых, 2 выключенных**. Очередь содержит **96 корзин** (24×4) первоначально со статусом PENDING; никакой результат заранее не объявлен успешным.
3. Не изменяй `main`, `mode.txt` (production normal), адресата/токен Telegram, raw query, лимиты, search enabled/disabled, blacklist, ручные hidden IDs, seen, секреты, рабочий бот/телефон. Не запускай production `monitor.py`, не отправляй реальные уведомления, не устанавливай APK на физический телефон; user ZIP и прочие личные данные не публикуй. Работа ведётся в Cloud ветках с безопасными тестовыми данными.

## ПРИОРИТЕТ: что нужно довести до корректности

**1. Фактический retrieval.** Для всех 24 групп (приоритет P0, затем P1) сравни конфигурационный запрос, `monitor.py` API q / HTML _nkw, `query_variants.py`, Android `SearchRequestRules.kt`, `QueryVariants.kt` и `QueryDisplay.kt`. Логируй ВСЕ реально попробованные алиасы и настройки: category, location (Германия vs worldwide), price floor, sorting, page length, BIN/AUC, best offer. Не теряй дешёвые корректные объявления из-за категоризации, слишком высокого `_udlo`, узкого запроса, скобок OR, неверного `LH_PrefLoc`, лимита API или пагинации. Не добавляй автоматические `-defekt`/`-ersatzteil`: `kein Ersatzteil` и `ohne Defekt` — не брак.

**2. Четыре корзины для каждого товара.** Независимо проверяй `Sofort` (FIXED_PRICE без Best Offer), `Sofort+` (FIXED_PRICE с Best Offer), `Auktion` (AUCTION без Best Offer), `Auktion+` (AUCTION с соответствующим Best Offer). Не предполагай, что stored listingType==одна из четырёх корзин, отдельный search может быть `all`. Для гибридов сравни отдельные BIN и bid, итоговую цену с доставкой/налогом, 24-часовое правило аукциона и наличие/окончание лота. Ошибка запроса не является честным `Не найдено`.

**3. Независимая eBay проверка, а не mocks.** Если доступен Playwright/Cloud Browser, открой реальную выдачу и сами item pages. Бери исходный поиск + приоритетные 3–5 алиасов; расширяй до 6–8 только если найден пропуск, избегай ненужного массового обхода. Для каждой группы цель **40–50 разных реальных item ID** (из всех корзин суммарно, с разметкой корзины), либо **весь фактически доступный каталог** с объяснением малого числа. Проверяй собственный title, модель и item specifics, seller/рейтинг именно этого лота, seller full description/iframe, condition, current price, shipping, import, location, buying options и endTime. В отчёте каждому релевантному кандидату нужен URL/ID, UTC время, источник browser-live/API/HTTP/индекс/fixture, полный verdict и подтверждающий факт. Без проверенного полного описания нельзя считать пригодность доказанной. При CAPTCHA/block не обходи защиту и не генерируй новые запросы насильно; отмечай BLOCKED с причиной.

**4. Кому отказывать.** Чёткие отрицательные vs положительные случаи: iPhone 16/17 Pro Max и неподходящие поколения/replica; Samsung S25 Edge ≠ S25/S25 Ultra и S24 Ultra; Pixel 5 ≠ Pixel 4a 5G/8a; Redmagic 11 Pro ≠ 11S Pro и Transparent Edition ≠ Transparent Case; Nubia Z70 ≠ Z70S, Z80 Ultra ≠ Leading/LV; Logitech Superlight 2 ≠ DEX/2C/Superstrike; WH-1000XM6 ≠ WF и аксессуары. 5070 Ti/4080 должны быть установленной GPU в продаваемом **ПК**, не отдельной картой/ноутбуком; OLED ноутбуков 4050/4060 и Asus Vivobook 14X — **собственная** OLED панель и подходящая GPU; LG UltraGear 480Hz, Odyssey G6 500Hz — именно правильная панель/модель. PS5 Pro целиком ≠ накладки, привод, DualSense, VR, игры, коробка. Дефекты и заменённые компоненты — по собственному описанию с корректной обработкой отрицаний (`nicht repariert`, `kein Defekt`); **не вводи запрет сторонней батареи без согласия пользователя**, и **не блокируй ПК только за отсутствие накопителя**.

**5. Настоящий blacklist.** Сверь глобальный запрет продавца `talk point gmbh`, search-specific excludeSellers и **16 hidden item IDs** в read-only manifest. Выделяй seller из собственного лота, не отзывов/рекомендаций и не рекламного магазина. Seller-ban vs hide-item vs аксессуар — разные причины. Не бань продавца только за неподходящий товар, не меняй ни один действующий список без явного решения владельца. Проверь Python/Kotlin паритет.

**6. Специальные regressions:** `189051391793` — заменённое заднее стекло -> отказ; `128121409205` — допустимый по модели аукцион, проверь seller/endtime в реальном Android HTTP; `117448535436` — iPhone с неправильными характеристиками -> отказ. `358301335572` — Redmagic Transparent, раньше уже не было в продаже, не принимать автоматически; `227534369510` — Redmagic 11 Pro, предыдущая ставка выше лимита 400€. `126954426838` — привод PS5, не консоль; `267796949271` — PS5 Pro с приводом по названию, но дорогая. `318411668191`, `137293505007` — экраны iPhone; `327358392023` — рамка Nubia Z80. Перед новыми статусами всегда перепроверять живые страницы. Старые 41 fixture-кейса — контрольная база **только по заголовку**, не доказательство доступности и цен.

## Как именно работать и сохранять доказательства

- Начни с `python tools/cloud-check.py --bot-dir ../e-monitor --android-dir .` из каталога Android (если папки соседние); бот отдельно `python qa/run_unit_tests.py`, Android `./gradlew testDebugUnitTest assembleDebug`, Java 21 и Android SDK 36. Указывай реальные запущенные тесты, failing cases, исходную и конечную SHA.
- Проверка по шагам: (а) real browser candidate -> (б) собственные данные seller, pricing, condition, description, time -> (в) прогон Python + Kotlin на идентичном вводе -> (г) запись confirmed false positive / false negative -> (д) исправление обеих реализаций или объяснение несовпадения контракта -> (е) регрессионный fixture + unit + Cloud readiness CI -> (ж) повторная проверка браузером. Исправляй только доказанные ошибки; пользовательский manifest не перезаписывать.
- В обоих `docs/qa/CLOUD_ACCEPTANCE_QUEUE_2026-10-08.json` обновляй статусы корзин из `PENDING` в `PASS/FAIL/BLOCKED/UNVERIFIABLE/NO_RESULTS_CONFIRMED` **с доказательствами**, числом уникальных лотов и ссылкой на отчёт. `NO_RESULTS_CONFIRMED` — только после *успешной* выдачи с проверенными алиасами/корзинами, НЕ на eBay ошибке, API quota, timeout, CAPTCHA или пустом body. Если невозможно подтвердить PASS — оставляй BLOCKED/PARTIAL.
- Подробные публичные отчёты в боте `qa/results/cloud-live-YYYYMMDD/`, в Android `docs/qa/cloud-live-YYYYMMDD/` (или ссылки на единый bot evidence без копирования больших снимков). Минимальный отчёт: product, raw query, alias, bucket, url, item_id, UTC timestamp, observed title, seller, actual listing type, model, condition, descriptionVerified, price, shipping, total, region, endtime, source, expected/actual Python/Android, verdict, reject reason. Не сохраняй cookie, токен, пароль или персональные данные.
- Прогресс сохраняй **каждые 3–5 групп** (или раньше при блокировках) коммитами в обоих `codex/cloud-work` вместе с исправлениями, тестами, evidence, очередью и обновлённым `docs/WORK_STATE.md`. Проверяй параллельные изменения, не перетирай чужую работу; без reset/clean/force push. Изменение логики Python требует корректного bump `logic_version.txt` **в Cloud** по AGENTS; это не развёртывание на сервер.
- Убедись, что Android CI **для актуального HEAD** зелёный; дай URL Actions и SHA-256 debug APK. Зелёные тесты не доказывают физическую установку или Telegram-доставку. Отдельный приёмочный отчёт: все **24 × 4** корзины, реальные сравнения, пропущенные дешёвые товары и ложные допуски, исправления, оставшиеся BLOCKED и отдельный список задач для ПК/телефона. Если нет браузера, вынеси live-browser часть в отдельный blocker, а не фальсифицируй её.
